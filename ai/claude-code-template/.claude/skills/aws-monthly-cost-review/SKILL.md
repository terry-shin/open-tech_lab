# AWS月次コストレビュー手順

Cost Explorerの実データを使って、指定した2ヶ月間のサービス別コストを比較し、
増減の大きいサービスについて原因を深掘りする。

## 0. 起動条件・ガードレール（必ず守る）

- **このSkillはユーザーが明示的に実行を指示したときのみ動作する。**
- **月次の自動実行はサポートしない。** `/loop`の固定間隔モードは7日で自動失効するため、
  30日間隔の運用には使えない。ユーザーが毎月手動でこのSkillを呼び出す運用を前提とする。
- **読み取り専用。** Cost Explorer・リソース調査ともに参照系APIのみを使用し、変更・削除系の
  AWS操作は一切行わない。
- 使用するAWSプロファイル名・アカウントIDの対応は、プロジェクト `.claude/CLAUDE.md` の
  「用語集」「aws-mcp 利用時の注意事項」を参照する（本Skill内では重複定義しない）。
- **秘密情報の出力は禁止。** パスワード・APIキー・トークン等が結果に含まれる場合は`***`に置換する。
- 想定外に大規模な範囲（多数のアカウント横断、長期間、全サービスの深掘り等）を求められた場合は、
  実行前にコスト感（API呼び出し回数の見込み）をユーザーに提示し確認を取る。
- 本Skillの成果物（サマリ・報告）は、ユーザーが明示的に依頼しない限り、Slackやissueコメント等
  他システムへの投稿は行わない（このセッション内での提示のみ）。

## 1. パラメータの確認

以下をユーザーに確認する。指定がなければデフォルト値を提案し、承認を得てから進める。

| パラメータ | 確認内容 | デフォルト |
|---|---|---|
| 対象環境 | 本番/STG/開発/運用のどれか | なし（必須確認） |
| 対象期間 | 比較する2つの月 | 直近の完了済み2ヶ月（例: 今日が8月なら6月・7月） |
| 除外閾値 | 両月とも月額がこの額未満のサービスは比較対象から除外 | $100 |
| 深掘り閾値 | この条件を満たしたサービスのみ自動で深掘りする | 差額の絶対値が$500以上 **または** 増減率30%以上 |

## 2. 事前チェック

1. 対象環境に対応するAWSプロファイルのSSOトークンが有効か確認する
   （`aws sts get-caller-identity --profile <対象プロファイル>`、または `mcp__aws-mcp` 経由）
2. 接続先アカウントIDが対象環境のものと一致するか確認する（用語集のアカウントID表と照合）
3. 軽量なCost Explorer呼び出し（当日1日分の `GetCostAndUsage` 等）で `ce:GetCostAndUsage` 権限があることを確認する
4. トークン切れ・権限エラーが出た場合は、プロジェクトCLAUDE.mdの「接続エラー・認証切れ」対応手順をユーザーに案内する

## 3. 月次・サービス別コスト取得

対象の2ヶ月それぞれについて取得する。

```
aws ce get-cost-and-usage \
  --time-period Start=<月初>,End=<翌月月初> \
  --granularity MONTHLY \
  --metrics UnblendedCost \
  --group-by Type=DIMENSION,Key=SERVICE \
  --profile <対象プロファイル>
```

`mcp__aws-mcp` 経由の場合は `aws___run_script`（`call_boto3`で`ce:GetCostAndUsage`を呼ぶ）を使う。
`aws___call_aws` は2026年8月31日に削除予定のため使用しない。

## 4. 比較・増減の特定

1. 2つの月のいずれでも月額が除外閾値未満のサービスは比較対象から除外する
2. 残ったサービスごとに `差額 = 後月コスト - 前月コスト` と `増減率` を算出する
3. 差額の絶対値が大きい順にサマリ表を作成する（サービス名・前月・後月・差額・増減率）

## 5. 深掘り調査（閾値超えのみ自動実行）

「差額の絶対値が深掘り閾値以上」または「増減率が深掘り閾値以上」のサービスについてのみ、
以下を自動で行う。閾値未満のサービスはサマリ表への掲載のみとし、深掘りはしない。

1. 該当サービスについて `USAGE_TYPE` または `USAGE_TYPE_GROUP` でのGroupByを追加し、コスト内訳を確認する
2. 実リソース側の要因（新規作成・スケールアップ・不要リソースの放置等）を確認する必要がある場合、
   サブエージェント `aws-resource-investigator` に委譲する
   - 委譲前に、対象環境のプロファイル選択・SSO認証・接続先アカウント確認を完了させておく
     （`aws-resource-investigator` 自身はこれをコーディネーター側の前提としている）
   - 深掘り対象サービスが多数（目安: 4件以上）ある場合は、全件を一度に並列委譲せず、
     優先度（差額の絶対値が大きい順）を提示してユーザーに確認してから進める
3. `aws-resource-investigator` からの報告は、そのエージェント内部の検証（`report-verifier-protocol`）を
   経たものとして扱う

## 6. 報告の作成・検証

1. 以下の構成でドラフトを作成する
   - サマリ表（増減額の大きい順、除外閾値・深掘り閾値の設定値を明記）
   - 深掘りしたサービスごとの原因（判明した事実と推測部分を明確に区別する）
   - 深掘りしなかったサービス（閾値未満）は増減額のみの一覧として添える
   - **深掘りしたサービスに限り**、コードブロック内にASCII文字によるバー表現を添える（下記参照）
2. ドラフト作成後、最終報告として提示する前に `report-verifier-protocol` の手順に従い
   `report-verifier` サブエージェントに検証を依頼する
   - `CONTEXT` には `REPO_ROOT` の代わりに、対象AWSプロファイル名・アカウントID・対象期間を記載する
3. 検証結果に応じてドラフトを修正し、最終報告としてユーザーに提示する

### ASCIIバー表現（深掘り対象サービスのみ）

深掘りしたサービスごとに、コードブロック内で以下の形式のバーを添えて増減を視覚化する。
外部ツール・Artifact等は使わず、テキストのみで完結させる。

```
<サービス名>   <前月> ███████░░░░░░░░░ $<金額>
             <後月> ███████████████░ $<金額>  (<増減率>)
```

- バー全体の幅は20文字とし、当該サービスの前月・後月のうち大きい方の金額を満杯（20文字）とした
  相対値でスケーリングする（サービスごとに独立したスケール。他サービスとの絶対比較はしない）
- 深掘り対象外（閾値未満）のサービスにはバーを付けない（サマリ表のみで十分なため）

## 出力フォーマット

- 結論（増減が大きかったサービスとその原因）を先に述べ、詳細を後に記載する
- サマリ表は必ず表形式で提示する
- 推測に基づく記述は「(推測)」等で明示する
- Cost Explorerから取得した数値はそのまま提示し、加工した値（差額・増減率）は算出方法を明示する
