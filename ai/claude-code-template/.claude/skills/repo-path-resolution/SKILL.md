# リポジトリパスの特定

このスキルをプリロードしているエージェント自身の本体（システムプロンプト冒頭）で、
以下2つの変数が宣言されていることを前提とする。

- `REPO_LABEL`: 対象リポジトリの表示名（例: `app`）
- `PATH_FILE`: `~/.claude/` 配下のパス設定ファイル名（例: `app-repo-path.txt`）

調査を始める前に、必ず以下の手順でリポジトリパスを特定する。

## ステップ1: 設定ファイルの確認

`~/.claude/${PATH_FILE}` が存在するか確認する:

```bash
cat ~/.claude/${PATH_FILE} 2>/dev/null
```

- **ファイルが存在してパスが読み込めた場合**: そのパスを `REPO_ROOT` として以降の調査で使用する
- **ファイルが存在しない、または空の場合**: 以下のステップ2に進む

## ステップ2: 初回セットアップ（パス未設定時）

設定ファイルが存在しない場合は、調査を行わず **以下のメッセージをそのまま出力して終了する**
（`<REPO_LABEL>` / `<PATH_FILE>` は実際の値に置き換える）:

```
## SETUP_REQUIRED

<REPO_LABEL> リポジトリのパスが未設定です。

呼び出し元の Claude に対して以下を依頼します:
1. ユーザーに「<REPO_LABEL> リポジトリのディレクトリパスを教えてください（例: /Users/<username>/git/<REPO_LABEL>）」と質問する
2. ユーザーから受け取ったパスを、**チルダを展開した絶対パスで**保存する:
   echo "$(eval echo 'ユーザーが入力したパス')" > ~/.claude/<PATH_FILE>
   ※ `~/git/...` の形のままファイルに書いてはいけない。後続の `REPO_ROOT=$(cat ...)` では
     シェル変数内のチルダが展開されず、`ls: ~/git/...: No such file or directory` で必ず失敗する
3. 保存後、このエージェントを再度呼び出す
```

## ステップ3: パスの検証

設定ファイルから読み込んだパスを検証する:

```bash
REPO_ROOT=$(cat ~/.claude/${PATH_FILE})
# 旧形式（`~/git/...`）で保存された設定ファイルを救済する。
# シェル変数内のチルダは展開されないため、$HOME に置換してから使う。
REPO_ROOT="${REPO_ROOT/#\~/$HOME}"
ls -d "$REPO_ROOT"
```

以降の調査では、ここで正規化した `REPO_ROOT` を使う（設定ファイルを毎回 `cat` し直さない）。

- **存在する場合**: そのパスを `REPO_ROOT` として調査を進める
- **存在しない場合**: 以下を報告して終了する:

  > 設定ファイル `~/.claude/${PATH_FILE}` に記載されたパスが存在しません。
  > 正しいパスに更新してください: `echo '正しいパス' > ~/.claude/${PATH_FILE}`

- **アクセス不可（権限未許可）の場合**: `additionalDirectories` / `--add-dir` で対象パスを許可するようユーザーに促す。

## 厳守事項（このスキルの範囲）

- `~/.claude/${PATH_FILE}` への書き込みは、初回セットアップ時（ユーザーから受け取ったパスの保存）に限り許可する。それ以外の対象リポジトリへの書き込みは、このスキルをプリロードしているエージェント自身の厳守事項に従う。
