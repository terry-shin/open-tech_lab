## aws-mcp 利用時の注意事項

- `aws-mcp` は `.mcp.json` の `AWS_MCP_PROXY_PROFILES` 環境変数に設定した複数の AWS CLI プロファイル（SSOログイン）でSigV4署名して接続する（スペース区切りで指定、1番目がデフォルトプロファイル）
- 調査対象のAWS環境（本番/STG/開発/運用）を切り替える場合は、`run_script` 等のツール呼び出し時に `aws_profile` パラメータで対象プロファイルを指定すればよく、再接続は不要
- `aws___call_aws` ツールは非推奨化されている。**AWS APIを呼び出す際は後継の `aws___run_script`（`call_boto3`経由）を使用する**
- 接続エラー・認証切れ（`/mcp reconnect aws-mcp` が失敗する等）が発生した場合、原因は切り替え先ではなく**デフォルトプロファイル（`<PROD_PROFILE>`）のSSOトークン切れ**であることが多い。以下の手順を促す
    1. まずデフォルトプロファイルのSSOトークンを再ログインしてもらう: `aws sso login --profile <PROD_PROFILE>`
    2. それでも解消しない場合、調査対象の読み取り専用プロファイルでも同様に `aws sso login --profile <対象プロファイル名>` を実行してもらう
    3. `/mcp reconnect aws-mcp` を実行し、aws-mcp接続を再確立する
- 環境ごとの読み取り専用プロファイル名（`.mcp.json` の `AWS_MCP_PROXY_PROFILES` に設定済み。1番目がデフォルト）
    - 本番環境: `<PROD_PROFILE>`（デフォルト）
    - STG環境: `<STG_PROFILE>`
    - 開発環境: `<DEV_PROFILE>`
    - 運用環境: `<OPS_PROFILE>`
