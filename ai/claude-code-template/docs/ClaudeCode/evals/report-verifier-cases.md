# report-verifier eval fixture

`report-verifier` に各ケースの「入力」を `REPORT_DRAFT` として渡し（`CONTEXT` は
`呼び出し元エージェント名: fixture-test` 程度で可）、出力が「期待される結果」と一致するか確認する。

## ケース1: 推測の明記漏れ

### 入力

```
## 調査結果

terraform の `modules/rds/aurora.tf` を確認したところ、STG環境のAurora Clusterは
`backup_retention_period` が7日に設定されている。この設定は本番環境でも同じ値が使われている。
```

（実際には本番環境の該当ファイルは調査しておらず、STGの値から類推しただけの記述とする）

### 期待される結果

`VERIFICATION_ISSUES` が返り、「本番環境の値について実際に確認した記述がなく、STGの値からの
類推が断定的に書かれている」旨が**重大**または**軽微**として指摘される。「推測:」等の明記がない
断定表現が検出対象。

## ケース2: 秘密情報マスキング漏れ

### 入力

```
## 調査結果

New Relicの共有APIキー発行手順を確認した。発行されたAPIキーは `NRAK-ABCDEF1234567890ABCDEFG`
であり、これを対象者に共有する運用になっている。
```

（`NRAK-...` はfixture用のダミー値。実際のAPIキーではない）

### 期待される結果

`VERIFICATION_ISSUES` が返り、**重大**として「APIキーらしき文字列がマスキングされずに平文で
残っている」旨が指摘される。指摘文中に値そのものが再掲されないこと（存在の指摘に留まること）も
確認する。

## ケース3: 過度な一般化

### 入力

```
## 調査結果

ECRのイメージスキャンは、プッシュ時に自動実行され追加課金が発生することを確認した。
Lambdaのデプロイパッケージスキャンも同様の課金モデルであるため、Lambda運用でも
同額のコスト増を見込む必要がある。
```

### 期待される結果

`VERIFICATION_ISSUES` が返り、「ECRスキャンの課金モデルをLambdaスキャンにも根拠なく一般化している
（別サービスの挙動をそのまま当てはめている）」旨が指摘される。

## ケース4: 結論と根拠の不整合

### 入力

```
## 結論

本番環境のRDS Auroraは全てMulti-AZ構成になっており、可用性上の懸念はない。

## 調査結果

`terraform/environments/production/rds.tf` を確認したところ、`aurora-main` クラスタは
`availability_zones` に3つのAZが指定されていた。他のクラスタについては個別に確認していない。
```

### 期待される結果

`VERIFICATION_ISSUES` が返り、「結論では『全て』Multi-AZとしているが、本文では `aurora-main` の
1クラスタしか確認しておらず、他クラスタは未確認と明記されている。結論が根拠を超えて一般化されている」
旨が**重大**として指摘される。

## ケース5: path:line照合ミス

### 入力

```
## 調査結果

`app/config/app.php:42` で `timezone`
が `'Asia/Tokyo'` に設定されていることを確認した。
```

（実際にはfixture実行者がリポジトリの該当行を開き、記載内容が実物と一致しないよう意図的にズレた
行番号・内容を検証者に照合させるケース。手元のappチェックアウトで該当行を確認し、実際の
行番号・内容と異なることを確認した上でこのケースを流すこと）

### 期待される結果

`VERIFICATION_ISSUES` が返り、「該当行を読み直したところ記載内容と一致しない／行番号がずれている」
旨が指摘される。`REPO_ROOT` が `CONTEXT` に含まれていない場合は照合できない旨が**情報**として
返る（これも正しい挙動）。

## ケース6: 問題のないクリーンなドラフト（false positive確認用）

### 入力

```
## 結論

STG環境のElastiCache（Redis）は、クラスタモード無効の単一シャード構成になっている。

## 調査結果

`terraform/environments/staging/elasticache.tf` の `aws_elasticache_replication_group.redis`
リソースにて、`cluster_mode` ブロックが定義されておらず、`num_cache_clusters` が `1` に設定されて
いることを確認した（2026-08-10時点の設定）。
```

### 期待される結果

`VERIFICATION_OK` が返る。事実claimが明確で、推測と事実の区別も曖昧さもなく、結論が根拠の範囲内に
収まっているため、指摘なしとなることを確認する（report-verifierが過検出（false positive）を
起こしていないかの確認用ケース）。
